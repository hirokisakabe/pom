# Findings — 3 分類によるギャップ一覧と推奨アクション

6 アーキタイプの HTML / pom 比較から抽出した差分を、issue #800 の方針通り 3 分類で整理する。

凡例:

- **影響度**: 🟥 大（複数アーキタイプで決定的に劣る）/ 🟧 中（1〜2 アーキタイプで顕著）/ 🟨 小（あれば嬉しい）
- **推奨アクション**: 既存 issue 紐づけ / 新規 issue 起票案 / `pom-slide` skill or `llm.txt` 改善 / 仕様明文化

## C. PPTX 原理限界 — PPTX 仕様上不可能

`pptxgenjs` / `PowerPoint` のどちらかが扱えない、または OOXML 仕様にない機能。実装で追えるものではなく、代替表現として整理する。

| #   | 仕様外の表現                                           | 代替表現                                                                                                                                                                              |
| --- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | `backdrop-filter: blur(10px)` (ガラス調)               | 半透明 `surface` 色（`backgroundColor` + `opacity`）+ 薄 1px border + ドロップシャドウ。"擬似ガラス" として `pom-slide` skill にレシピ化候補                                          |
| C2  | `mask-image` / 任意の SVG マスク（CSS grid mask など） | PPTX は shape geometry の組み合わせで近似可能だが汎用マスクは無理。装飾を弱める方向で再設計するか、画像書き出し（Image ノード）で逃げる。表紙のグリッドパターンはこの代替策で吸収する |
| C3  | アニメーション / 動画的トランジション                  | 静的スライド前提。アニメは PowerPoint 側の機能で別物                                                                                                                                  |
| C4  | フォントのウェブロード（任意 TTF を CDN から）         | pom-cli が同梱する `Carlito` / `Noto Sans CJK JP` / `Noto Sans JP` の範囲内で組む。`pom-theme.json` で `typography.fontFamily` を環境固有フォントに設定するパターンを案内             |
| C5  | `box-shadow: 0 0 60px ...` のような外側拡散グロー      | `shadow.type="outer"` + 大きい `blur` で近似。色付きは効くが、HTML の真の外側拡散とは滲み方が異なる                                                                                   |

## 既存起票済み issue との対応

机上比較で起票された #793〜#798 はすべて本調査開始時点で **CLOSED**。本調査では実例ベースで以下を再確認:

| 機能               | 関連 issue | 実例で確認した出現頻度 / 妥当性                                                                    |
| ------------------ | ---------- | -------------------------------------------------------------------------------------------------- |
| グラデーション塗り | #793       | 表紙 / KPI / 比較 / 引用すべてで使用。机上推定通り「不在なら見栄えが大幅劣化」する筆頭機能だった   |
| rotate             | #794       | 本調査では使用機会なし。装飾 SVG (45° 切り出し) などで本領発揮。表紙の装飾アーク回転で活用余地あり |
| 辺ごと border      | #795       | KPI タイルで明確に詰まった。**`borderRadius` 併用不可がボトルネック**。A3 で再起票検討             |
| letterSpacing      | #796       | 表紙の display タイトル、各 eyebrow ラベル、フッタなどで多用。机上推定通り高頻度                   |
| flex 比率 (grow)   | #797       | KPI / 比較で 4 等分・2 等分に大活躍。机上推定通り頻度高                                            |
| 文字エフェクト     | #798       | 表紙タイトル / 引用符で活用。Shape にも欲しいケース複数（A5）                                      |

## 結論

- **机上の事前見立て（#793〜#798）は妥当**だった。実例で叩いても投資対効果の優先順位は変わらない
- **未発見の決定的な機能ギャップは「テキストグラデーション」と「radial-gradient」の 2 つ**。両者とも表紙の華やかさを左右する基幹機能。両方とも pptxgenjs 経由で（または XML 後処理で）実装可能。次の四半期に着手する価値あり
- **語彙ギャップは想定より大きい**。`pom-slide` skill のレシピを「Theme トークン + Layer 装飾 + 6 ロールパレット」の組み合わせで書き直すと AI 生成物の質が体感で 1 段上がるはず（特に `<Theme>` ヘッダから書き始める習慣、accent2 を含めた 6 ロール、`Layer` 装飾レイヤ）
- **PPTX 原理限界は HTML を完全に追わない方針が現実的**。`backdrop-filter` / mask-image / 任意フォントロードは諦め、半透明 surface + drop shadow / ImageNode フォールバックで吸収する旨を skill に明文化
- 本調査の方法（同一お題で HTML / pom を並べる）は **3 分類のワークフローが機能した**。次の四半期にも同じお題で回せば、A1 / A2 / A3 などが入った後の改善が画像比較で観察できる。継続的 eval として定着させる価値あり
